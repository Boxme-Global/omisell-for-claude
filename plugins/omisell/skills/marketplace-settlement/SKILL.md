# Omisell: marketplace settlement

Goal: the accountant knows how much is still waiting on each marketplace, how much has landed, and which orders to dispute.

## Steps

1. **Period.** Turn the user's period into unix seconds in the business time zone. `settlement_reconciliation` filters on the **order creation date** and accepts **at most 31 days**. For a longer period, answer the latest 31 days and offer the earlier months one by one.
2. **Reconcile.** Call `settlement_reconciliation` with `date_from`, `date_to`, `limit` 10 (max 20). Add `store_id` only when the user names one channel (get it from `list_stores`). It returns three tabs, each with `orders`, `expected`, `received`:
   - `to_release` - awaiting payout from the marketplace,
   - `released` - paid out,
   - `abnormal` - amount mismatch (expected vs received),
   plus `abnormal_samples` (order code, platform, expected, received, difference), largest mismatch first, and a `note`.
3. **Payment status (optional).** If the user also asks about unpaid / partly paid orders, call `payment_status_breakdown` with the same window (max 90 days) and `group_by` `"channel"` or `"payment_status"`. It counts **payment records, not orders** (an order with a partial payment or refund counts more than once); say so. Its `key` is a code; show the name: 100 Unpaid, 110 Payment processing, 120 Payment pending (debt), 150 Partially paid, 200 Paid, 300 Refunded, 310 Partially refunded, 500 Voided, 550 Cancelled COD, 600 Overdue.
4. **One order in detail.** If the user picks a mismatched order, call `order_fee_breakdown` with `tracking_codes` [that code] to show its fee lines. Up to 20 codes in one call; never loop one call per order.
5. **Refused.** `missing_permission` on step 2 → "This needs the order payment reconciliation permission in Omisell (Finance > Order payment reconciliation)." Then still run step 3 if the user can see orders. On step 4 the area is "order costs".

## Answer

- Summary: awaiting payout total and order count, paid-out total, mismatch count and its total difference, with the period ("orders created 01/10-31/10/2026").
- Table 1: the three tabs - orders, expected, received.
- Table 2: top mismatched orders - order code, channel, expected, received, difference. Say how many more mismatches exist (`abnormal.orders` minus rows shown).
- Read the `note` and pass on its caveat in plain words: "received" only counts marketplace transactions already recorded, so a payout that lands in a later period can make an order look unpaid.
- Next: open the mismatched orders in Omisell (Finance > Order payment reconciliation) to dispute; `/omisell:fees-by-channel` for the fee side; `/omisell:overdue-payments` for unpaid orders.

## Do not

- Do not treat `expected` minus `received` of the to-release tab as money lost: that tab is simply not paid yet.
- Do not explain why a mismatch happened unless a tool result shows it. A received amount near 0 on an old order may be a payout not yet recorded; say "check it on the reconciliation screen, and tell Omisell support if the marketplace already paid".
- Do not show store ids. Show platform codes as the marketplace name (`shopee_v2` → Shopee, `lazada` → Lazada, `tiktok` → TikTok Shop), never the raw code.
