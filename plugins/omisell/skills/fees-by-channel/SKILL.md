# Omisell: fees by channel

Goal: the accountant sees what each marketplace charged in the period, which fee types weigh most, and what was charged on an order that looks wrong.

## Steps

1. **Period.** Unix seconds in the business time zone, **at most 90 days**, filtered on the **order creation date**.
2. **By fee type.** Call `fee_aggregate_by_channel` with `date_from`, `date_to`, `group_by` `"fee_code"`. Add `channels` (platform codes such as `shopee`, `lazada`, `tiktok`) when the user names channels. Rows are `{key: fee code, total}`, largest first; zero codes are left out.
3. **By channel.** Call it again with `group_by` `"channel"` and `fee_codes` set to the marketplace fee columns: `commission_fee`, `transaction_fee`, `service_fee`, `campaign_fee`, `sponsored_affiliates`, `infrastructure_fee`, `other_fee`, `fsm_fee`, `lcp_fee`, `pi_ship`, `wrong_weight_adjustment`. Without `fee_codes` the channel total adds every column, shipping and refund lines included, which is not a fee total. The tool only sums columns, so this figure is **marketplace fee columns, before fee refunds and excluding seller-paid shipping**. Say which fees the channel total covers, show the `refund_*` and seller-paid shipping lines from step 2 separately, and do not compare it with the per-order `expenses` total (that one also nets refunds and adds seller-paid shipping).
4. **Specific orders.** When the user names orders (Omisell `OD...` codes or marketplace order codes), call `order_fee_breakdown` with `tracking_codes` (up to 20 in one call). It returns the non-zero fee lines per order; `not_found` lists codes it could not match. To find orders paid a different amount than expected, use `/omisell:marketplace-settlement`; this skill has no tool that lists "abnormal fee" orders on its own.
5. **Refused.** `missing_permission` → "This needs the order cost permission in Omisell (Finance > Order costs), or Cost management." Nothing else in this skill works without it; say so and suggest `/omisell:marketplace-settlement` if the user has that permission instead.

## Fee names

Show fee codes as plain names in the user's language: `commission_fee` commission, `transaction_fee` payment / transaction fee, `service_fee` service fee, `campaign_fee` campaign fee, `sponsored_affiliates` affiliate commission, `infrastructure_fee` infrastructure fee, `fulfill_fee` fulfilment fee, `other_fee` other fees, `subsidy_platform` platform subsidy, `refund_*` refund of that fee, `*shipping_fee` shipping lines (buyer-paid, seller-paid, original, logistics, return-to-seller), `wrong_weight_adjustment` wrong-weight adjustment, `flexi_combo`, `fsm_fee`, `lcp_fee`, `pi_ship` keep the code with "(marketplace fee)". From `order_fee_breakdown` also: `expenses` total fees, `crosscheck_amount` expected payout, `nmv_final` NMV, `platform_ship_rebate_for_seller` platform shipping rebate. Any other key: a plain-language reading of it plus "(marketplace fee line)". Never show the raw code alone. Show platform codes as the marketplace name (`shopee_v2` → Shopee, `lazada` → Lazada, `tiktok` → TikTok Shop), never the raw code.

## Answer

- Summary: marketplace fees per channel (before fee refunds, excluding seller-paid shipping) and the biggest fee type, with the period ("orders created 30/10-05/11/2026").
- Table 1: channel - fees charged before refunds (step 3). It is not expected to equal the sum of Table 2, which covers every column, shipping and refund lines included.
- Table 2: top 8 fee types - name, total. Show amounts as the tool returns them, sign included; do not flip signs or add a fee rate the tool did not return.
- For orders: one block per order code with its fee lines.
- Next: compare with payouts (`/omisell:marketplace-settlement`), profit after cost (`/omisell:gross-margin`), one order end to end (`/omisell:explain-order`).

## Do not

- Do not compute a fee percentage of revenue: no tool here returns revenue on the same basis.
- Do not loop `order_fee_breakdown` one order at a time; pass the codes together.
