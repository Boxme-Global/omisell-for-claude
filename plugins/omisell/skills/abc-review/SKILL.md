# Omisell: ABC review

Goal: split the catalogue into A / B / C so the user knows which SKUs to keep in stock first and which ones tie up money without selling.

## Steps

Default window: the last 90 days (sales grading needs a longer view than 7 days; say so). The user may pick a shorter one; the tools accept at most 90 days.

1. **Grade by sales.** `inventory_abc_analysis` with `by="product"`, `date_from`, `date_to`, `limit=500`. A = products making up the first 80% of sales value, B = the next 15%, C = the last 5%. Rows come highest sales first and carry `grade`, `sku`, `quantity_sold`, `discounted_sale_price`, `percent_sales`; `grades` has each grade's share and value (no product count); `currency` is the money unit. Compare `count` with `total_matched`: when `count` is smaller the list is cut off at the low-selling end, so grade counts come only from the rows returned (say "of the top N by sales"), and a SKU missing from it is "outside the top N by sales", not "no sales".
2. **Grade by stock value.** `inventory_abc_analysis` with `by="inventory"` (no dates: stock right now), `limit=100` (highest stock value first). Same 80 / 15 / 5 split, on stock value at cost (`cogs`); rows also carry `quantity` and per-warehouse `inventories`. Pass `pickup_id` only when the user asks about one warehouse; pass `brand_id` only when they name a brand.
3. **Sell-through**, after steps 1-2. `sell_through_rate` with the same `date_from` / `date_to`, `skus` = the top 10 A-by-sales SKUs plus the capital-stuck candidates below (or the SKUs the user named; at most 200), `limit=200`. `percent_sold` is a RATIO: units sold ÷ stock at the start of the window, 0.15 = 15%. Multiply by 100 before showing it and compare the ratio with 0.20. A SKU with no sales in the window has no row: its sell-through is 0%. When no stock record exists before the window, the tool estimates the start stock as stock now + units sold, so treat low-volume rows as rough.
4. If a call is refused, say which part is missing in plain words and answer with the other two.

## Reading the grades together

Match rows by SKU and point out:
- **Protect**: A by sales. Check their days of stock left (`/omisell:stockout-forecast`).
- **Capital stuck**: A or B by stock value but C by sales, or `percent_sold` below 0.20 (under 20%) in the window. Candidates for a promotion, a stock transfer or no reorder.
- **Tail**: C by sales and C by stock value. Low priority either way.
- A SKU that is A or B by stock value but missing from the sales grading: if the sales list was complete (`count` = `total_matched`), list it under "no sales in the window"; if it was cut off, call it "outside the top N by sales".

## Answer

- Summary: how many products are A / B / C by sales ("of the top N" when cut off) and what share of sales A carries; how much stock value (with currency) sits in SKUs that sell little; window "90 days to <dd/mm/yyyy>" and "stock as of now".
- Table 1, A by sales (top 10): SKU · name · units sold · sales value · stock-value grade · sell-through %.
- Table 2, capital stuck (top 10 by stock value): SKU · stock qty · stock value · sales grade · sell-through %.
- Next: forecast stock-outs for the A list (`/omisell:stockout-forecast`), plan reorders for A SKUs only (`/omisell:reorder-plan`), clear slow stock (`/omisell:dead-stock-decision`).

## Do not

- Do not mix currencies: use the `currency` each result returns.
- Do not call the stock-value grade "best sellers"; it ranks money in stock, not sales.
- Do not grade SKUs yourself from another tool's numbers; use the grades the tool returns.
