# Omisell: overdue payments

Goal: the accountant has the list of orders to chase for payment, split into orders still open and orders already closed.

## Steps

1. **Age.** `find_overdue_payment_orders` takes `days_overdue` (default 7, 1-365): it means the **order was created at least N days ago** (and within the last year) and has a payment that is overdue (600), payment pending (debt) (120) or partly paid (150). It is not a due date. Use the user's number, else 7, and say which.
2. **Open orders.** Call `find_overdue_payment_orders` with `days_overdue`, `exclude_cancelled` true, `limit` 50. Add `channels` (platform codes) or `payment_types` (1 COD, 2 bank transfer, 3 card, 4 cash, 5 internet banking, 6 QR code, 7 online banking, 8 installment, 9 store credit, 10 gift away, 11 debt) only when the user names them. Returns `total` and `samples` (order code, created time, platform), oldest first.
3. **All orders.** Call it again with `exclude_cancelled` false. The difference between the two totals is orders already cancelled or completed whose payment record is still marked overdue / debt / partial: they need checking, not chasing.
4. **Mix (optional, when the user asks "how much is unpaid overall").** Call `payment_status_breakdown` with `date_from` + `date_to` (both required; unix seconds, order creation, at most 90 days; default the last 30 days and say so) and `group_by` `"payment_status"` (or `"channel"`, `"payment_type"`). It counts **payment records, not orders**. Show the code as its name: 100 Unpaid, 110 Payment processing, 120 Payment pending (debt), 150 Partially paid, 200 Paid, 300 Refunded, 310 Partially refunded, 500 Voided, 550 Cancelled COD, 600 Overdue.
5. **Refused.** `missing_permission` → "This needs the order view permission in Omisell." There is no fallback.

## Answer

- Summary: open orders to chase (count) older than N days, plus how many closed orders still carry an overdue payment record.
- Table: oldest 15 open orders - order code, channel, created date (dd/mm/yyyy). Say how many more (`total` minus rows shown).
- Mix table (if step 4 ran): payment status - records, with the period.
- Next: open the orders in Omisell to record the payment; one order in detail `/omisell:explain-order`; marketplace payouts `/omisell:marketplace-settlement`.

## Do not

- Do not show amounts: these tools return no amount owed. Say so if asked and point to the order screen.
- Do not print the numeric order status from the samples. Show platform codes as the marketplace name (`shopee_v2` → Shopee, `lazada` → Lazada, `tiktok` → TikTok Shop), never the raw code.
- Do not change a payment status from this skill. If the user asks to mark orders paid, say it is done on the Omisell order screen.
