# Omisell: e-invoice status

Goal: the accountant knows how many e-invoice requests are done, stuck or failed for a revenue period, and where to fix them.

## Steps

1. **Window.** Unix seconds in the business time zone, **at most 90 days**. The tool counts requests whose **revenue period lies entirely inside the window**, so a request spanning the window's edge is left out. For "this month", use the whole calendar month.
2. **Status.** Call `einvoice_status` with `date_from`, `date_to`; add `store_id` (from `list_stores`) only for one channel. It returns `statuses` (one row per status with `label` and `count`), `totals` (`orders`, `orders_processed`, `orders_completed`, `price`) and a `note`.
3. **Refused.** `missing_permission` → "This needs the VAT statement / e-invoice permission in Omisell." There is no fallback.

## Answer

- Summary: requests completed vs failed vs still waiting, and the amount covered, with the window ("revenue periods within 01/10-31/10/2026").
- Table: status (`label`) - requests. Then orders covered, processed, completed, amount.
- If `failed` > 0, say so first, and that the failed requests are listed on the Omisell e-invoice screen.
- Pass on the `note` in plain words: the e-invoice screen is not filtered by warehouse, so every staff member sees the whole business; totals are the figures saved when the request was made, and the Excel export is the reference if they differ.
- Next: open Finance > E-invoices in Omisell to retry failed requests or issue new ones; revenue for the same period `/omisell:revenue-report`.

## Do not

- Never issue, cancel, retry or re-send an invoice from Claude. Point to the Omisell screen.
- Do not list individual invoices or buyers' tax details: the tool returns counts only.
