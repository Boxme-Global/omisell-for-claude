# Omisell: dead stock decision

Goal: split dead stock into "clear it" (stock still on hand) and "stop selling it" (nothing left, no demand), and carry out the stop-selling part safely.

## Steps

1. **Stock with no sales (clear it).** `dead_stock_summary` with `days_no_sale` = the user's number of days (default 60, allowed 7-365), `limit: 200` (rows come back ordered by quantity, so sort them by `sub_total_price_sale` yourself before picking the top 10; when `total_matched` is above 200, say the value ranking covers only the 200 SKUs with the most stock). Read `total_quantity`, `total_price_sale` (value at sale price, in `currency`), `total_matched`, and per SKU `name`, `sku`, `quantity`, `sub_total_price_sale`. Add `pickup_id` only if the user names one warehouse.
2. **Out of stock with no orders (stop selling).** `discontinue_candidates` with `days_no_sale: 180` (or 90 if the user wants a looser cut; allowed 30-730, but only 90 and 180 can be discontinued in bulk), `limit: 20`. Read `total_matched`, `buckets` (count at 90 and 180 days), and per product `sku`, `name`, `linked_total`, `linked_active` (channel listings still linked), `last_order_time`.
3. If the user already asked to discontinue, also call `dry_run_discontinue_all_candidates` (read-only, see Writes) so the answer shows the count and groups. Present the lists (see Answer) and ask what to do. Do not call a write tool (`update_product_active`, `discontinue_all_candidates`) in this turn.

## Writes

Discontinuing sets the product inactive in Omisell. It does NOT delist it on the channels, stop stock pushes or block new orders; say this in the preview.

- **A few chosen SKUs (up to 200).** `dry_run_update_product_active` with `skus` → show `eligible`, `out_of_scope`, `not_found`. When the user agrees, `update_product_active` with the eligible `skus` and `is_active: false` → show its preview → on a clear yes to that preview, `confirm_action` with the `request_id` and `confirm_token` → `get_action_status`.
- **The whole candidate set, or one group of it.** `dry_run_discontinue_all_candidates` with `range_days` 90 or 180 (same as step 2) and no `segment` → show `total_matched` and the `segments` breakdown in plain words:
  - `live_marketplace` / `stale_marketplace`: still listed active on a marketplace (recently synced / not synced lately)
  - `live_webstore` / `stale_webstore`: still active on a website channel
  - `pos_only`: only on POS or internal channels; `unknown_channel`: active on an unidentified channel
  - `dormant`: listings paused or inactive; `delisted`: listings deleted; `unlinked`: no listing at all

  Suggest starting with the safest groups (`unlinked`, `delisted`, `dormant`) and checking marketplace listings before including them. When the user picks the scope, call `discontinue_all_candidates` with the same `range_days` and the chosen `segment` (omit it for all) → show the preview count → on a clear yes, `confirm_action` → `get_action_status` (it runs in the background; if still `executing`, say so and offer to check again).
- Write tools missing from the tool list → say writing is not enabled on this connection and point to the product list in Omisell (Products), where products can be set inactive.

## Answer

- Summary: how much stock value is sitting unsold (with the days used) and how many products could be discontinued.
- Table 1 (clear it): SKU · name · quantity · value at sale price, top 10 by value, "and N more".
- Table 2 (stop selling): SKU · name · listings still active · last order date (or "never"), top 10.
- Suggest per table: clear stock with a discount or a promotion (`/omisell:sync-stock-price` to push prices, `/omisell:campaign-overview` for promotions); discontinue the second list with a preview here.
- After a write: how many products were set inactive, how many failed and why, and the reminder that channel listings are unchanged.

## Do not

- Do not discontinue products that still hold stock; those belong in Table 1.
- Do not call `confirm_action` on the dry-run result, or on a yes given before the preview was shown.
- Do not put prices on sale from this skill.

**Writes: preview, confirm, check.** Write tools only PROPOSE: they return a preview, a `request_id` and a one-time `confirm_token`. Show the preview (what changes, how many items, anything blocked). Prefer a `dry_run_*` tool first when one exists; when none does, the write tool's own proposal is the preview.
